## Detailed Vulnerability Reports

### SEC-01: Hardcoded Legacy Project Credentials in Client Bundle
- **Severity**: **CRITICAL**
- **Affected Files**:
  - `src/lib/supabase.ts` (lines 3–7)
  - `dist/assets/*.js` (generated by `vite build`)
- **Evidence**:
  ```ts
  const DEFAULT_SUPABASE_URL = 'https://mpjjetxtpekrxeyivlkv.supabase.co';
  const DEFAULT_SUPABASE_ANON_KEY = 'sb_publishable_k9lCl5klWC5Xlz4omL6TIQ_g7Jr5Cns';

  const supabaseUrl = import.meta.env.VITE_SUPABASE_URL || DEFAULT_SUPABASE_URL;
  const supabaseAnonKey = import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY || import.meta.env.VITE_SUPABASE_ANON_KEY || DEFAULT_SUPABASE_ANON_KEY;
  ```
  `grep_search` confirmed `https://mpjjetxtpekrxeyivlkv.supabase.co` is bundled directly into the compiled JavaScript bundle.
- **Exploitation / Failure Scenario**: If environment variables are omitted or misconfigured, the frontend automatically attempts to authenticate against and query a decommissioned/old Supabase project.
- **Required Fix**:
  1. Remove `DEFAULT_SUPABASE_URL` and `DEFAULT_SUPABASE_ANON_KEY` entirely.
  2. Read canonical `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (with fallback to `VITE_SUPABASE_ANON_KEY` for legacy compatibility).
  3. Validate that `VITE_SUPABASE_URL` is a valid `https://*.supabase.co` URL and the key is non-empty.
  4. If invalid or missing, expose a clear unconfigured state without throwing an unhandled exception.
- **Acceptance Criteria**:
  - `grep` for `mpjjetxtpekrxeyivlkv` yields 0 matches in source and `dist/`.
  - When environment variables are missing, the app renders a user-friendly setup screen rather than crashing.

### SEC-02: Fail-Open Owner Authorization in AuthContext & App Router
- **Severity**: **CRITICAL**
- **Affected Files**:
  - `src/context/AuthContext.tsx` (lines 50–62)
  - `src/App.tsx` (lines 104–106)
- **Evidence**:
  ```ts
  // src/context/AuthContext.tsx lines 50-61:
  if (ownerError) {
    // Table may not exist yet if migrations haven't run
    const status = { isOwner: true, ownerConfigured: false, userId: user.id };
    setOwnerStatus(status);
    return status;
  }
  const configured = ownerRows && ownerRows.length > 0;
  const isOwner = configured && ownerRows[0].owner_user_id === user.id;
  const status = { isOwner: !configured || isOwner, ownerConfigured: configured, userId: user.id };
  setOwnerStatus(status);
  ```
  And in `src/App.tsx`:
  ```ts
  // Lines 104-106:
  if (ownerStatus?.ownerConfigured && !ownerStatus?.isOwner) {
    return <AccessDeniedPage />;
  }
  ```
- **Exploitation Scenario**:
  1. An attacker registers an account on an unconfigured or fresh instance. Because `app_owner_config` has no rows, `configured` is `false`.
  2. `!configured || isOwner` evaluates to `true`. `isOwner` is set to `true`.
  3. `ownerStatus?.ownerConfigured && !ownerStatus?.isOwner` evaluates to `false`.
  4. The attacker is admitted to the full application as the owner!
  5. Furthermore, if the RPC or table check fails with a network/permission error (`ownerError`), `isOwner` is also set to `true`.
- **Required Fix**:
  1. In `AuthContext.tsx`, an error or unconfigured state MUST NEVER set `isOwner: true`.
  2. Separate the owner states into:
     - `loading`: Determining status.
     - `unconfigured`: No owner enrolled yet in database.
     - `owner`: Authenticated user matches server-side owner UUID.
     - `unauthorized`: Authenticated user does NOT match owner UUID.
  3. When `unconfigured`, render a dedicated **Owner Bootstrap Flow** allowing the designated administrator to claim the instance securely.
  4. Non-owners must be strictly routed to `AccessDeniedPage`.
- **Acceptance Criteria**:
  - Any error in owner checking results in access denial (`isOwner: false`).
  - An unconfigured database does NOT allow arbitrary users to access financial data.

### SEC-03: Insecure Storage & Client-Side Transmission of AI Secrets
- **Severity**: **HIGH**
- **Affected Files**:
  - `src/features/assistant/AssistantPage.tsx` (lines 53–78)
  - `src/domain/gemini.ts` (lines 354, 419)
- **Evidence**:
  ```ts
  sessionStorage.setItem('pft_gemini_key', key);
  // ...
  const url = `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent?key=${apiKey}`;
  const response = await fetch(url, ...);
  ```
- **Exploitation Scenario**: Storing the API key in `sessionStorage` and transmitting it directly to Google from client-side JavaScript exposes the key to any malicious script, rogue dependency, or browser extension. It also bypasses server-side token controls and context sanitization.
- **Required Fix**:
  1. Remove raw API key entry from client storage.
  2. In connected mode, invoke an authenticated Supabase Edge Function (`/functions/v1/gemini-proxy`) which reads `GEMINI_API_KEY` from Supabase Secrets.
  3. Ensure the proxy verifies the user's JWT and enforces outbound financial masking.
  4. Ensure the assistant falls back cleanly to the local deterministic engine when AI is unconfigured.
- **Acceptance Criteria**:
  - Zero instances of `sessionStorage.setItem('pft_gemini_key')`.
  - Zero direct client calls to `generativelanguage.googleapis.com`.

### SEC-04: Non-Atomic Financial Import Batch Persistence
- **Severity**: **MEDIUM**
- **Affected Files**:
  - `src/data/supabaseRepository.ts` (lines 351–377)
- **Evidence**:
  ```ts
  for (const evt of newEvents) {
    await this.addEvent(evt);
  }
  for (const evt of updatedEvents) {
    await this.updateEvent(evt.id, evt);
  }
  const { error } = await supabase.from('import_batches').insert({ ... });
  ```
- **Exploitation Scenario**: If an import containing 200 transactions fails at row 150 (e.g. rate limit, network drop, timeout), the first 150 events and postings remain committed to the database, but the `import_batches` record is never created. The user cannot view the batch, track its provenance, or click "Undo Import".
- **Required Fix**: Create a transactional RPC function `commit_import_batch` in PostgreSQL that accepts the batch descriptor and event array, performing the inserts within an atomic PostgreSQL transaction.
- **Acceptance Criteria**: A simulated mid-batch failure leaves 0 orphaned records and does not corrupt the ledger.

### SEC-05: Silent Local Repository & Demo Fixture Contamination
- **Severity**: **MEDIUM**
- **Affected Files**:
  - `src/context/LedgerContext.tsx` (lines 63–68)
  - `src/data/localRepository.ts` (lines 58–90)
- **Evidence**:
  ```ts
  const repository = useMemo(() => {
    if (user && isSupabaseConfigured) {
      return new SupabaseLedgerRepository();
    }
    return new LocalLedgerRepository();
  }, [user]);
  ```
- **Exploitation Scenario**: If the user's session expires or Supabase fails, `repository` switches to `LocalLedgerRepository`, which immediately loads `DEMO_FIXTURE` (fake accounts and mock events) into `localStorage`. The user sees synthetic data appear suddenly as if it were their real financial record.
- **Required Fix**: Enforce explicit application modes:
  - `cloud`: Strictly connects to `SupabaseLedgerRepository`. If connection or auth fails, display a clear, retryable error screen.
  - `demo`: Explicitly requested demo mode using in-memory or isolated demo state.
- **Acceptance Criteria**: No automatic fallback from cloud repository to local demo repository.

### SEC-06: Incomplete Authentication Workflows
- **Severity**: **MEDIUM**
- **Affected Files**:
  - `src/features/auth/AuthPage.tsx`
  - `src/context/AuthContext.tsx`
- **Evidence**: `AuthPage.tsx` provides only "Sign In", "Create Account", and "Sign in with Google". It does not offer "Forgot Password?", does not call `supabase.auth.resetPasswordForEmail()`, and does not handle password update callbacks.
- **Required Fix**:
  1. Add `resetPassword(email)` and `updatePassword(newPassword)` to `AuthContext.tsx`.
  2. Add "Forgot Password?" tab/modal to `AuthPage.tsx`.
  3. Listen for `PASSWORD_RECOVERY` events in `onAuthStateChange` and present a secure Password Reset modal.
- **Acceptance Criteria**: Verified end-to-end password reset email request and password update flow.

### SEC-07: Unvalidated Supabase Client Instantiation
- **Severity**: **LOW**
- **Affected Files**:
  - `src/lib/supabase.ts`
- **Evidence**: `createClient(supabaseUrl, supabaseAnonKey)` will throw an unhandled exception if `supabaseUrl` is an empty string or malformed.
- **Required Fix**: Use a safe singleton initialization pattern that handles missing configuration gracefully and returns a dummy/noop client or null when unconfigured.
- **Acceptance Criteria**: App renders without unhandled runtime crashes when env variables are empty.
