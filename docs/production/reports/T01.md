## Delivered behaviour

- **Unified Financial Command Service (F04 / AT02)**: Introduced `src/domain/commandService.ts` as the single validated domain entry point for all financial writes (`purchase`, `income`, `refund`, `fee`, `own_transfer`, `card_payment`). Enforces safe integer paise, strictly positive amounts, valid calendar dates, and distinct source/destination accounts. All UI entry routes (`AddEntryModal`, `QuickCaptureModal` [QuickText, Voice, Receipt], and `AssistantPage`) now route through this validated contract.
- **Carried Period Opening & Date Slicing (F16 / AT01)**: Refactored `calculatePeriodSummary` in `src/domain/ledger.ts`. Carries forward pre-period transactions (`event.date < fromDate`) into the opening position, ensuring the fundamental accounting invariant holds for any date range:
  $$\text{Carried Opening} + \text{Period Received Income} - \text{Period Net Spending} = \text{Closing Net Position}$$
  Verified both the full October month and the 5–31 October slice specified in AT01.
- **Card Statement Repayment Direction (F03 / AT02)**: Fixed `applyImportBatch` in `src/domain/reconciliation.ts`. When importing card statements, card credits are paired as: Bank debit (asset decrease, $-\Delta$) and Card credit (liability reduction, $+\Delta$). Corrected bank refund inference so that bank credits with "REFUND" or "REVERSAL" reduce spending rather than adding income.
- **Strict Calendar Date Validation (AT03)**: Added `src/domain/dates.ts` with strict calendar validation (`isValidCalendarDate`), rejecting impossible dates such as `2026-02-31`. Updated `normalizeDate` in `src/domain/importer.ts` to return `'REJECT'` for invalid dates.
- **Assistant Clarification & Dynamic Date Periods (F14 / AT03)**: In `src/domain/gemini.ts`, eliminated the fabricated default ₹120 when amounts are unstated; the assistant now explicitly requests amount clarification. Dynamic month/period parsing resolves queries like "November 2026" to `2026-11-01` through `2026-11-30`.
- **Interactive Accounting Period Selector**: Created `src/components/common/PeriodSelectModal.tsx` and connected it to the header date pill in `Header.tsx`, allowing the user to select between October 2026, 5–31 October 2026 slice, November 2026, Q4 Horizon, or custom date ranges.
- **Scope check**: Assigned task only (T01). No database migrations or authentication changes from subsequent tasks were touched.
