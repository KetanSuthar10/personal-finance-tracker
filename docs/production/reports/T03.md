## Delivered behaviour

- **SupabaseLedgerRepository Integration**: Connected `SupabaseLedgerRepository` as production's durable data source within `LedgerContext`. In production mode when authenticated, all data reads and writes execute against remote hosted Supabase tables via RLS and the PostgreSQL `execute_financial_command` transactional boundary.
- **Fail-Closed Architecture**: Production starts completely empty for a new authenticated owner. If configuration is missing, authentication is expired/unauthorized, or a database query fails, the system fails closed with honest error handling (`persistenceError`). It explicitly prohibits falling back to `LocalStorage` or injecting `DEMO_FIXTURE` (F12).
- **Owner Account Lifecycle & Onboarding**: Added `addAccount` and `updateAccount` workflows:
  - Account creation modal supports liquid bank assets, cash wallets, and credit liabilities with safe integer paise validation (F18).
  - Opening balance adjustments preserve ledger history and show live balance impact previews (F18).
  - Empty onboarding view guides new owners when 0 accounts exist.
- **Distinct Recorded Activity vs Statement Date**: Distinguishes recorded balance date (`latest_recorded_date` / activity through date) from the last statement-confirmed date (`latestStatementDate`) on account cards (F16).
- **Cross-Device Sync on Focus**: Added window `focus` event listener in `LedgerContext` to automatically re-fetch remote ledger state when switching back to the app on phone or laptop (AT14).
- **In-Memory Cleanup on Sign-Out**: When an owner signs out, the application unmounts the `<LedgerProvider>` and releases all in-memory accounts and transactions immediately, preventing cross-session retention or leakage.
- **Clean Production UI**: Stripped milestone badges and development debug boxes from ordinary user shells and navigation sidebars (F23).
